## 4. 模块分解（s01–s18）

<!-- 每屏：目的 / 布局区域 / 数据模型 / 交互 / 状态 / 验收标准 / 必须保留的边界；与设计大图 1:1 对应 -->

### s01 此刻 · 时间主权

**设计大图**：`design/01_桌面大图/01_此刻_时间主权.png`（对应图号 01）。

**目的**：首页以“要保护的一段时间”为主对象（今晚 19:00—20:00），同时呈现当前容量缺口（10 分钟）与一个需要用户决定的单一问题，把用户下一步引向“查看可行做法”。

**布局区域**：
- 左侧图标导航栏：此刻 / 时间 / 收件 / 协同 / 回顾 / 边界，底部搜索（⌘K）与头像。
- 顶部品牌行：留白 / PERSONAL TIME；右侧“概念设计 · 演示状态”徽标与日期（09.12 · 星期六）。
- 主区“时间意图”卡：衬线大字 19:00—20:00；副文案“不自动填入工作。暂时没有用途，也成立。”；暖色警告 pill“当前计划超出容量 10 分钟”；主动作“看看可行的做法 →”与诚实副文案“还没有修改任何安排”；开放椭环视觉。
- 右列决策卡“01 此刻，只需一个决定”：问题“怎样把这十分钟找回来？”；并列 120（可用时间/分钟）与 130（当前投入估计/分钟）；两个候选方向：“准备报告草稿，减少从零开始（预计减少 20 分钟，仍需你检查确认）”与“或者，把行政事项移到明天”。
- 下区“02 没有被悄悄改变的责任”三张责任卡：已确认会议 30 分钟（固定约定 · 不自动移动）、报告交付 60 分钟（19:00 截止 · 标准不变）、行政事项 40 分钟（个人计划 · 可以重新决定）。
- 页脚：覆盖范围声明（工作日历、任务清单、指定文件；其他生活安排仍需确认）与“界面为独立演示状态；不代表已连接、已执行或真实收益”。

**数据模型**：
- `protectedBlock`：`{ start: "19:00", end: "20:00", purpose: null, lockedBy: "localRule" }`（用途允许为空）。
- `capacity`：`{ availableMinutes: 120, plannedMinutes: 130, gapMinutes: 10 }`。
- `commitments[]`：`{ title, minutes, kind: "固定约定" | "截止任务" | "个人计划", mobility: "不可自动移动" | "可重新决定" }`。
- `decision`：`{ question, options: [{ label, expectedReductionMinutes?, note }] }`；状态字段 `modifiedAnything: false` 支撑“还没有修改任何安排”。

**交互**：主动作与右列候选方向均进入 s04 方案页；责任卡只读展示移动性，不提供“悄悄移动”入口；搜索唤起全局快捷输入（s14）。

**状态**：
- 空态：未设置保护时段时给出发起保护的入口；无容量缺口时显示“容量充足”，不得编造缺口。
- 失败/过期：来源未同步时账本数据标注过期并保留上次数据，不回退为空列表（§05）。
- 边界：缺口为 0 或负值时如实显示；未连接真实来源时演示数据必须带“演示状态”徽标。

**验收标准**：
1. 首屏视觉主对象是保护时段 19:00—20:00，而不是任务完成量。
2. 容量缺口 10 分钟以文字 + 暖色 pill 双重呈现。
3. 页面不出现“已优化 / 已节省”字样；主动作旁可见“还没有修改任何安排”。
4. 三张责任卡各自显示移动性属性，且没有批量移动入口。

**必须保留的边界**：没有执行变更不能写成已优化；不自动填入工作；暂时没有用途也成立。

### s02 时间账本 · 责任与边界

**设计大图**：`design/01_桌面大图/02_时间账本_责任与边界.png`（对应图号 02）。

**目的**：以“安排与责任”和“你选择的边界”两条轨道呈现同一天，使 19:00 的容量冲突直接可见，并保证留白不能被自动侵占。

**布局区域**：
- 标题区：“时间有去向，也有边界。”；副文案“固定约定、可变计划与留白分开记录；空白不自动意味着可占用。”
- 日历卡：日期 9 月 12 日，今日/本周切换，时区 UTC+8；时间轴 17:00—20:30 分双列：左轨“安排与责任”依次为已确认会议（30 分钟 · 固定约定，带锁形图标）、报告交付（预计投入 60 分钟，pill“19:00 前提交”）、行政事项（40 分钟 · 暂定计划），其越界部分以斜线阴影 + “超出边界 10 分钟”警告呈现；右轨“你选择的边界”含胶囊“未提前安排的时间 ≠ 必须工作”与“受保护的留白 19:00—20:00”卡（“没有用途，也不接受自动填充。”）。
- 轴底说明：“需要改变完成路径，或由你重新决定可变事项。”
- 右列“01 今天的容量”：120 分钟可用 / 130 分钟当前预计投入 / 10 分钟容量缺口（暖色）。
- 右列“02 每件事都保留来源”：工作日历 17:00 已同步；任务清单 17:00 已同步；其他安排 未覆盖（暖色）。
- 右列收束卡：“移动，不等于节省。如果把工作移到明天，今天会更宽裕，但未来责任仍在。”＋主动作“查看可行方案 →”。

**数据模型**：
- `dayTimeline`：`{ date, timezone, lanes: { responsibility: TimelineEvent[], boundary: ProtectedBlock[] } }`。
- `TimelineEvent`：`{ title, start, end, minutes, kind: "固定约定" | "暂定计划" | "截止任务", sourceRef, overflowMinutes? }`。
- `sourceRegistry[]`：`{ name, lastSyncAt, coverage: "已同步" | "过期" | "同步失败" | "未连接" | "未覆盖" }`。
- `conflict`：`{ range: "19:00—20:00", gapMinutes: 10, overflowEventId }`。

**交互**：今日/本周切换；事件点开查看来源与状态；越界/冲突区域跳转 s04；暂定计划可由用户重新决定；留白卡只读，不响应拖拽填充。

**状态**：
- 空态：轨道为空时显示来源说明与手动记录入口，不伪造现成任务（§05）。
- 来源过期/失败：事件保留并标注最后成功同步时间与范围，不当作空闲。
- 边界：计划侵入保护段时以斜线阴影 + 警告呈现；“其他安排 未覆盖”必须显示为未知，不得折算成可用容量。

**验收标准**：
1. 双轨在视觉上可区分，且各自有列标题。
2. 19:00 冲突以越界阴影 + “超出边界 10 分钟”文字同时呈现。
3. “其他安排”行显示“未覆盖”，页面任何位置不把它呈现为空闲。
4. 留白卡不可被拖拽或自动填充。

**必须保留的边界**：未同步不是空闲；空白不自动意味着可占用；移动，不等于节省。

### s03 收件箱 · 请求不等于承诺

**设计大图**：`design/01_桌面大图/03_收件箱_请求不等于承诺.png`（对应图号 03）。

**目的**：把外部请求从“原话 + 来源 + 未知字段”完整呈现到用户确认为止，明确区分请求、意图与已接受责任。

**布局区域**：
- 标题区：“先理解，再成为责任。”；副文案“把外界的请求放进收件箱，不直接放进你的人生。”
- 左列“待澄清（3）”列表：竞品分析 · 会议提及（来源：项目例会摘录，尚未接受）；下周碰一次方案（来源：邮件 · 陈同事，时间待确认）；找个晚上练琴（来源：自己 · 快捷记录，个人意向）；底部文案“允许一个想法一直只是想法。收集，不等于接受。”
- 中列详情卡：状态 pill“请求 · 未确认”；标题“三种方案的差异”；元信息“例会摘录 · 09:32 · 合成示例”；原话引用块“下周可以看看三种方案的差异。”；“影响判断的四件事”字段组：提出者＝陈同事（演示人物）、谁已接受＝尚未确认（暖色）、截止期限＝尚未约定（暖色）、预计投入＝尚未估计；说明“只有你的确认，才会把它变成你的责任。系统不会替你回答‘我来做’。”；三个动作：我接受这件事（主动作）/ 保留为想法 / 不是我的事项。
- 右列“01 提取不是承诺”三步：已提出（会议中出现的请求）→ 待确认（系统提取出的候选事项）→ 已接受（只有你能建立这份责任）。
- 右列收束卡：“AI 只补问必要的问题。你是否愿意接受这件事？确定之后，再讨论范围与时间；不要求先填写一整套项目表格。”＋ pill“不自动向任何人发送消息”。

**数据模型**：
- `request`：`{ id, verbatim, sourceRef: { type, excerptAt }, requester, status: "已提出" | "待确认" | "已接受" | "保留为想法" | "已排除", acceptedBy: null, deadline: null, effortEstimate: null }`——未知字段必须保持 null 并显示占位词。
- 列表项派生字段：`sourceLabel`、`statusLabel`。

**交互**：列表项切换详情；“我接受这件事”将状态置为已接受并进入责任范围/截止时间讨论；“保留为想法”“不是我的事项”分别归档或排除；任何动作都不触发对外发送。

**状态**：
- 空态：无请求时显示来源渠道说明与手动记录入口。
- 未知态：谁已接受 / 截止期限 / 预计投入未知时显示“尚未确认 / 尚未约定 / 尚未估计”，系统不得代填。
- 失败：原话缺失时展示摘要但明确标注“原话缺失”，不得伪装成原话。

**验收标准**：
1. 原话引用块与来源元信息同屏可见。
2. 三个处置动作齐全，且接受动作不产生任何对外消息。
3. 四个判断字段全部呈现，未知值用暖色占位词而非默认值。
4. “提取不是承诺”三步进度中“已接受”未点亮。

**必须保留的边界**：请求不能自动升级为承诺；收集不等于接受；系统不代答“我来做”，不自动向任何人发送消息。

### s04 自适应方案 · 改变方法与分工

**设计大图**：`design/01_桌面大图/04_自适应方案_改变方法与分工.png`（对应图号 04）。

**目的**：并排比较“减负”与“延期”两条路径的不同后果，把预计减少与未来负担分开记账，让用户选择而非被安排。

**布局区域**：
- 标题区：“换一种做法，不挤掉自己。”；副文案“同一个结果，两条路径。改变的是做法，不是偷偷降低承诺。”
- 约束条：当前约束“19:00 前可用 120 分钟；当前预计投入 130 分钟。”；chips：会议不动 / 交付标准不变 / 19:00—20:00 留白 / 方案未执行（暖色）。
- 方案 A 卡（减少人的投入）：“先准备，再由你判断。AI 整理指定材料与比较草稿。你从检查和取舍开始，不再面对空白页。”；衬线数字 60 → 40 分钟（报告的预计人工投入 · 新估计包含检查与修改）；行项：预计减少人工投入＝20 分钟、19:00 前预计总投入＝110/120 分钟、仍需你完成＝内容检查与最终确认；主动作“选择这条路径 →”与副文案“下一步预览具体授权”。
- 方案 B 卡（把负担移到未来）：“今天放下，明天仍在。把行政事项移到明天。今天更宽裕，但这份责任不会消失。”；衬线数字 40 分钟（从今天转移到明天的工作量）；行项：预计净节省＝没有发生、19:00 前预计总投入＝90/120 分钟、明天新增负担＝40 分钟（暖色）；次动作“预览延期的影响 →”与副文案“不会算作节省时间”。
- 页脚：“估计不是事实。执行期间会更新人工投入，必要时重新检查可行性。”＋“保留原计划”。

**数据模型**：
- `plan`：`{ id, version, kind: "reduceEffort" | "defer", constraints: string[], estimate: { beforeMinutes, afterMinutes, expectedReductionMinutes, totalAfter, humanTasksRemaining }, futureDebt?: { minutes, dueDate }, status: "候选" | "选中" | "待批准" | "失效" }`。
- `expectedReductionMinutes` 一律为估计值，展示时必须带“预计”限定。

**交互**：选择方案 A → s05 变更预览；方案 B 的“预览延期的影响”→ 延期影响视图（仍不入账节省）；“保留原计划”→ 返回 s02；执行期间估计更新后需重新检查容量（§06）。

**状态**：
- 方案状态机入口：候选 → 选中；来源变化后置为失效并提示重新检查（§05）。
- 空态：无候选方案时显示来源与约束，不编造方案。
- 边界态：实际核对超过估计时，回到容量检查并允许撤回选择。

**验收标准**：
1. 方案 A 的“20 分钟”出现在“预计减少人工投入”行内，且注明新估计包含检查与修改。

### s10 我的边界 · 权限与暂停

**设计大图**：`design/01_桌面大图/10_我的边界_权限与暂停.png`（对应图号 10）。

**目的**：把读取、准备、写入与外部动作的权限分级呈现为可读规则，提供规则变更记录与一步暂停路径。

- `ruleChangeLog[]`：`{ version, at, actor: "本人" | "AI 建议", diff }`——AI 建议只有本人确认后才改版本。
- `automation`：`{ paused: boolean, preservedState: "原始事项与未完成责任仍然可见" }`。

**交互**：切换规则分组；修改任一权限生成新版本与变更记录；“查看规则变更记录”展示版本历史；“立即暂停”一步停用全部自动化且保留事项可见性。

**状态**：
- 保护状态机入口：本地规则有效 / 外部写入中 / 外部待核验 / 已覆盖指定渠道（§05）。
- 权限申请：模型请求新权限时只能生成建议，等待本人逐条确认。
- 暂停态：暂停后不清空上下文，恢复时延续原状态。

**验收标准**：
1. 六项权限各自显示分级徽标与限制说明，无一仅靠颜色区分。
2. 规则版本（08）与确认时间（09.12 09:10）可见。
3. “立即暂停”一步可达，且保留事项可见性的说明存在。
4. “不得从其他许可推导授权”文案出现在付款行。

**必须保留的边界**：模型不能自行扩大权限；发送不视为可完全撤回；付款、购买与新增承诺不开放。

### s11 私人上下文 · 来源与推测

**目的**：把本人意图、事实来源与系统推测分层保存与呈现，提供修正、撤销与导出能力，让“了解你”不变成“占有你”。

**验收标准**：
1. 意图行显示“由你明确表达 · 可修改、暂停或删除”。

3. “其他生活安排”显示“未接入 · 不能推断没有安排”。

**必须保留的边界**：推测不能升级为事实；了解你不等于占有你；不把行为指标当作生活目标；撤销只控制后续访问。

### s13 同步异常 · 未知与接管

**设计大图**：`design/01_桌面大图/13_同步异常_未知与接管.png`（对应图号 13）。

**目的**：在部分同步失败时把本地保护与外部保护分开呈现：本地规则仍然有效，外部状态保持未知，并给出重试、原工具接管与降级三条出路。

**布局区域**：
- 标题区：“不知道的时候，就说不知道。”；副文案“数据未同步不等于没有安排。外部保护未核验，就保持待确认。”
- 左卡：pill“⚠ 部分来源未同步”；主标题“今晚的保护，尚未完整核验。”；说明“留白中的规则仍然保留。但因为个人日历暂时无法更新，不能确认外部预约是否看见这段不可用时间。”；绿色确认卡“✓ 本地规则仍然有效——19:00—20:00 不接受留白内部的自动填充。”；暖色待确认卡“⚠ 外部日历保护待确认——尚未核验忙闲投影与最新冲突。不会显示‘已全面保护’。”；动作“重新同步与核验”（主动作，刷新图标）与“打开原日历 ↗”；脚注“失败记录会保留；重试不会重复创建同一保护事件。”
- 右列“01 目前知道什么”：工作日历 17:02 已同步；任务清单 17:00 已同步；个人日历 16:41 后未同步（暖色）；家庭日历 尚未连接。
- 右列收束卡：“可以继续，不必假装完整。暂时使用本地计划时，不会把未知时段分配给新的自动任务；你仍可以在原工具中接管。”；动作“暂用本地计划 →”。

**数据模型**：
- `syncStatus[]`：`{ source, lastSuccessAt, state: "已同步" | "过期" | "同步失败" | "尚未连接" }`。
- `protectionState`：`{ local: "有效", external: "待核验" | "写入中" | "已覆盖指定渠道" }`（§05 保护状态机）。
- `retry`：`{ idempotent: true, failureLog: [] }`；重试按保护事件幂等键去重。

**交互**：“重新同步与核验”按幂等键重试并在完成后更新外部状态；“打开原日历”跳出原工具接管；“暂用本地计划”进入降级模式——未知时段不参与自动分配。

**状态**：
- 保护状态机入口：本地规则有效 / 外部写入中 / 外部待核验 / 已覆盖指定渠道。
- 未知态：外部忙闲未核验时显示“待确认”，任何页面不得展示“已全面保护”。
- 失败态：保留上一份可用数据并标注时间；失败记录保留供排查。

**验收标准**：
1. 本地“仍然有效”与外部“待确认”两张状态卡并存且可区分。
2. “不会显示‘已全面保护’”文案可见。
3. 四个来源各显示最后成功时间或连接状态。
4. “重试不会重复创建同一保护事件”与“不会把未知时段分配给新的自动任务”可见。

**必须保留的边界**：外部保护未核验就保持未知；数据未同步不等于没有安排；可以降级继续，不必假装完整。

### s14 快捷输入 · 意图与约束

**设计大图**：`design/01_桌面大图/14_快捷输入_意图与约束.png`（对应图号 14）。

**目的**：把一句话输入拆成“意图”与“硬约束”，先理解再检查冲突，不从口语输入推导任何泛化授权。

**布局区域**：
- 标题区：“一句话，保留你的原意。”；副文案“轻量输入不意味着草率执行。先理解，再检查可行性。”
- 快捷入口卡（ESC 关闭）：原话衬线展示“明晚七点到八点留给自己，客户会议别动。”＋语音输入图标。
- “系统理解为”两张并列卡：
  1. ☾ 个人时间意图——9 月 13 日 · 19:00—20:00——当前时区 UTC+8 · 可修改 · 尚未创建日历事件。
  2. 🔒 不可擅自改变——现有客户会议——没有自动授予改会或发消息权限。
- 说明行：“下一步只检查冲突。需要改变安排时，再向你展示具体差异。”
- 动作：检查这段时间（主动作，放大镜图标）/ 只保存为意图；快捷键提示“⌘ Enter”；卡底“快速记录 / 自然语言 / 语音 / 分享到留白 · 同一套语义与授权边界”。

**数据模型**：
- `capture`：`{ verbatim, channel: "快速记录" | "自然语言" | "语音" | "分享", parsed: { intent: { type: "个人时间意图", start, end, timezone, calendarEventCreated: false }, constraints: [{ object: "现有客户会议", rule: "不可擅自改变", granted: [] }] } }`。
- `conflictCheck`：`{ status: "未检查" | "无冲突" | "有冲突", diffs? }`——有冲突时进入差异展示，不直接执行。

**交互**：解析结果可逐字段修改；“检查这段时间”运行冲突检查并按结果展示差异或确认保存；“只保存为意图”仅存意图，不创建日历事件；ESC 关闭不丢失已保存内容之外的输入草稿。

**状态**：
- 解析不确定：展示理解结果并标注可修改，不静默采用。
- 冲突态：与保护时段或客户会议冲突时只展示差异，等待用户决定。
- 空态：输入为空时显示来源、示例与手动记录入口（§05）。

**验收标准**：
1. 意图卡显示“尚未创建日历事件”。
2. 约束卡显示“没有自动授予改会或发消息权限”。
3. 两个动作均不产生任何外部变更。
4. 底部声明四个入口共用同一套语义与授权边界。

**必须保留的边界**：输入一句话不等于泛化授权；下一步只检查冲突，改变安排前展示具体差异；改会、发消息权限不被自动授予。
